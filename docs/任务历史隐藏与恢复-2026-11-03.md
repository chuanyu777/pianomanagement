# 任务历史隐藏与恢复（2026-11-03）

> 后续整合：确认单引用已改为每页 50 条、按首次出现次序去重并使用独立游标；Web 可翻页，并逐条向 Core 重查当前确认单与回执。数据来源已由 Core 按当前账号解析并授权后跳转。隔离 PostgreSQL 定向测试覆盖 50/51 边界、1001 条记录、跨页去重及隐藏后的访问。同源标签页使用 BroadcastChannel 通知，并在清理前重查当前账号的服务端状态；不支持该 API 或错过通知的标签页不能自动补收。以下保留最初阶段的记录；最终全量门禁以最新整合结果为准。真实浏览器多标签及双数据库资金操作后的审计保留仍未完成验证。

## 实现范围

- 任务详情可隐藏聊天展示。Core 使用当前登录身份签发限定任务的短期 Capability，经 HMAC 调用 Agent；Agent 仅将匹配身份的任务状态改为 archived，不删除消息、运行、事件、Core 回执、审计或领域流水。同一身份重复请求可重试。
- 历史读取和隐藏使用任务行锁串行化；隐藏后不再通过任务列表、详情、后续事件访问或新运行读取该任务。已开始的运行可以结束，数据仍保留。浏览器成功隐藏后清除本标签页中同任务的会话缓存。
- 消息按创建时间及 ID 倒序定位，每次返回最近 100 条，前端可按游标查看更早或较新一页；返回首页继续任务只使用最新一页。历史确认单在消息前按 Core 当前状态重查。
- 为控制单次返回量，确认单引用最多处理 1000 条原始事件引用，超出时明确提示不完整，用户应从业务页面核对。此上限不是确认单分页方案。

## 验证和限制

- 红绿测试覆盖 Agent 能力作用域、Core 签名请求、Web 隐藏和分页、回执顺序，以及隔离 PostgreSQL 的 501 条消息分页、1001 条确认单引用上限、读取与隐藏锁竞争、运行中隐藏后完成和数据保留。测试只清理隔离数据库中随机生成的测试记录。
- Web 测试使用模拟 HTTP，Core 网关测试与 Agent 数据库测试分开执行；尚未完成浏览器经过真实 Core、Agent 和双数据库的完整 E2E，也未验证 Core 业务审计与领域流水在真实资金操作后的保留。
- 本项定向历史页面测试 23 项通过；独立隔离 PostgreSQL 的分页和并发测试 2 项通过；Core 网关定向测试 17 项通过；单独构建、typecheck 和 lint 通过。最新完整门禁的 Web 测试 196 通过、1 失败：`App.test.tsx` 的课消用例未找到预期学生课程按钮；因此完整门禁未通过。项目代码在并行修改，不能据此推断最终整合结果。
- 已打开的其他浏览器标签页、已建立的 SSE 连接和其他设备上的本地缓存不会被此操作主动清空；隐藏不等于撤销确认或取消运行。历史确认单引用超过上限时不能完整恢复；游标分页与执行中的新消息交错、长时间运行及全设备尚未实测。
- 来源链接未实现：协议仅提供类型、ID 和标签；确认单历史清理会移除来源。课程账户 ID 不能安全推断学生，课次 ID 不能安全推断日历日期；可靠定位需要 Core 按当前身份授权解析原记录及明确的业务深链，不能信任历史标签或猜测。
