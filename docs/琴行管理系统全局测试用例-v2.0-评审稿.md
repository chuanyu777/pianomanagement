## 1. 用例说明和测试数据

角色 O=店主，T1/T2=两位老师；S1/S2为可区分但同名学生；C1主课60分钟、C2陪练45分钟。每例默认从独立数据库快照开始，业务月份开放，有权限、已有所需账户；特殊条件写在表中。除权限案例外以O执行。金额均为人民币十进制字符串，预期金额必须精确计算，不能使用有小数误差的结果。

阅读说明：优先看表中的操作步骤和预期结果；用例编号用于定位和关联自动化检查。

测试方式标记：双=AI发起/预览/用户确认与结构化入口分别跑；核=Core/API及真实数据库；对=对话/Agent；页=浏览器；环=Docker/恢复。双入口应以相同初始数据的独立副本比较余额、流水、状态、快照和关联关系；请求ID/时间/入口审计字段不要求相同。

P0=资金、安全、事务、期间及营业阻断；P1=其余冻结功能，交付同样必须通过。涉及方案D01–D10未决边界的参数先标记阻塞，不能自定规则或计入通过。

## 20. 完整业务流程测试步骤

以下对应方案第6节的J01–J12。每条流程按步骤操作并核对最终结果；涉及时间时使用可控制的测试时间，不能提前确认上课或直接改数据库状态代替用户操作。

### J01 新学生建档和首次上课

1. O登录，建T1/T2、C1/C2、S1/S2同名学生；通过选择卡定位S1。
2. S1开C1价200.00/C2价80.00；S2的C1用180.00；确认账户名册唯一。
3. S1/C1交费500.00、赠送80.00，S1/C2交费120.00、赠送20.00；保存记录ID。
4. 为S1/C1排T1主课，核60分钟；推进至结束后确认一次。
5. S1/C1=380.00/0.00，S1/C2=120.00/20.00；T1业绩200.00；课消与actor/回执关联。

### J02 交费、赠送、扣费和补交欠费

1. 从F1已完成一课状态开始，再在合法不冲突时间完成两节C1。
2. C1实收依次180.00、-20.00，C2不变，欠费名单出现S1/C1。
3. C1补交100.00后实收80.00，退出欠费名单，C2仍不变。
4. 问余额原因并展开每条流水，核500+100−120−200−200=80，赠送80−80=0。
5. 另起全赠送支付样本，确认不扣实收但业绩/课消完整计价。

### J03 修改单价、更换老师和撤销上课确认

1. C1旧价200.00完成T1一课；另一待上课仍未确认时改价180.00。
2. 后一课由T2按180.00确认；历史T1仍200.00，账户未转移。
3. O撤销后一课：追加原资金拆分的等额反向、回待上课；T2有效业绩归零。
4. 再次合法确认：仅新一轮180.00有效；流水链完整，无双倍净课消。

### J04 单节排课和按周批量排课

1. 建T1 09:00–10:00；相邻10:00可排，09:45冲突不得写。
2. 对待上课调到可用时段，再请假取消，余额/流水全程不变。
3. 另建每周19:00共12周计划，第6周制造既有冲突，确认整批未落库。
4. 改可行时间重预览整批确认12条；仅改第3条/取消第4条，其余不变，无第13周自动创建。

### J05 最终退学退款

1. 用独立F2副本；另设一个欠费副本验证不能以正余额课程抵欠。
2. F2预览显示逐课本金/赠送与手续费100.00，比例6.67%，实际1400.00。
3. 严格确认一次；两账户全零、退学，一张退款单及全部明细/清零流水原子可查。
4. 现金支出1400.00，经营手续费收入100.00，赠送清零不产生新收付款。
5. 余额并发变化副本验证旧预览失效；中途失败副本验证全回滚；未来课与纠错规则按D03/D05决策另验。
6. 另建实际退款与系统录入跨月副本，核现金按实际退款日归属、手续费按退款登记月归属；若日期字段含义尚未明确，登记D06阻塞，不自动以服务端创建时间替代业务日期。

### J06 工资计算、支付和两类月报核对

1. 使用独立F3、F4数据，登记所有固定分类及渠道样本，不能人工插报表结果。
2. 生成工资，修改该月基薪/比例/奖扣后核最终F3金额；改老师默认配置不能改原月。
3. 分别验证同月付款的F4精确总计，及另一副本跨月支付现金归属。
4. 未关账副本取消错误付款并重登，核净现金只一份工资，不影响所属月应发成本。
5. 分项对账F4，展开导致现金净额-380.00与经营利润190.00差异的真实记录。

### J07 在读、冻结和退学状态变化

1. 无完成课，从首账户创建时间推进至31天前、正好、后1ms，核在读/在读/冻结。
2. 冻结学生完成一课后恢复在读；其他课程新开户不能重置既有起算。
3. 独立最终退学生在任何时钟下保持退学；老师只能见自己授权名单。

### J08 关账、撤销关账和跨月纠错

1. 有经营记录的9月执行预检、关账，记录报表和流水摘要。
2. 对每类金额动作尝试写9月，全部拒绝；不能只隐藏按钮。
3. 用F5在10月追加9月错误课消200.00的反向及正确课消220.00；9月摘要不变、10月净课消20.00，账户实收780.00，原/反向/正确记录相互可追溯。另验交费冲正重登链。
4. 10月工资调整按D05已确认口径验收；10月再关账后拒绝直接重开9月。
5. 有原因撤销10月关账，缺原因拒绝；全过程关账不产生金额。

### J09 老师日常操作和权限检查

1. T1在独立浏览器登录，默认待办/课表只显示自己。
2. 查负责学生教学信息，调/取消自己的待上课，结束后确认一课，再查本人业绩工资。
3. 用AI、结构化页面、资源ID替换、回执链接、历史、导出分别访问学生金额、T2数据与全店报表。
4. 授权功能成功、越权全部无数据；不能以“AI拒绝了”代替接口级验证。

### J10 AI和手动页面操作、AI故障时的处理

1. 同源初始副本A走AI、B走结构化，每项关键动作比对状态、金额、流水类型和归属。
2. 关闭模型连接但保持Core服务，重走今日/课表/学生/流水/报表查询；按W01–W15逐项验证资料、账户、全部排课动作、交费/赠送/冲正、退款、工资生成/调整/支付/取消、手工收支及关账/撤销的人工入口，不用四个代表操作替代全局降级验证。未决D项按明确后的规则验收。
3. 工作区明确服务状态但不堆常驻工程说明，不丢登录/输入，不把模型故障说成退款失败。
4. 恢复模型后新任务可用，既成业务不得重新提交。

### J11 同时操作、断网和对话恢复

1. 两浏览器同时预览同课/账户，先一方成功，另一方必须重校验。
2. 对每个展开写操作跑X08；提交后断网恢复先查原请求，保留原业务ID。
3. Agent任务停在需补信息阶段，重启后恢复历史及检查点，继续补问不重演已完成动作。
4. SSE断线补读、worker失租、旧owner写入等由对应真实库用例验证，最后独立对账无差异。

### J12 Docker安装、重启和备份恢复

1. 对明确独立的测试卷执行文档化初始化，不复用已有开发数据掩盖缺步骤。
2. 初始化店主与Agent检查点，浏览器完成登录、交费、排课、确认和回执查询。
3. 重启容器，核业务/会话持久；备份并恢复到另一独立库再做只读对账。
4. 运行完整门禁及相关smoke，记录镜像/提交/命令和实际结果；本地未测试的生产项明确未验证。

## 21. 测试结果记录

本稿包含174条基础用例、12条完整业务流程，以及每种操作的通用检查项和AI表达/日期测试。174不是实际运行次数；同一用例还需分别测试适用的用户角色、操作入口和数据情况。

评审后逐条记录：`对应需求 | 用例编号和参数 | 操作入口和用户角色 | 操作前数据 | 预期结果 | 实际结果 | 状态 | 截图或记录 | 问题编号 | 修复后复测版本`。D01–D10等问题确认处理规则后，补充准确的输入和预期结果。未执行、不适用和阻塞分别统计，不计为通过。

是否可交付按方案第14节的测试通过标准判断：已确认功能能用、完整流程能完成、金额能核对一致，不能只看自动化脚本通过率。
