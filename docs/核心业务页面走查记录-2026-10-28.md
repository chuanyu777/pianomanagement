# 核心业务页面走查记录

本轮使用独立 Docker 数据库，从空数据走查；所登记的人员、金额和课程均为测试数据。走查范围是核心业务页面，不代表 AI 对话全量验收。

## 实际走查

| 流程 | 核对结果 |
| --- | --- |
| 基础资料 | 建立教师（底薪 1000 元、提成 20%）和 60 分钟课程（默认价 200 元）。 |
| 学生与账户 | 新建学生、为主课开通个性化单价 180 元的账户；交费 1000 元、赠送 100 元后余额分别正确。 |
| 排课与课消 | 单节课程排课并确认上课，180 元课消先扣赠送 100 元，再扣实付 80 元；实付余额变为 920 元。 |
| 最终退款 | 剩余实付 920 元，手续费 20 元，实际退款 900 元；账户余额清零、学生状态为退学。 |
| 工资 | 课程业绩 180 元、20% 提成 36 元，合计工资 1036 元；登记支付后显示已支付。 |
| 手工收支与报表 | 登记卖书收入 30 元；现金收入 1030 元、支出 1936 元、净额 -906 元，页面与经营报表核对一致。 |
| 关账 | 月份关账后尝试登记当月手工收支被拦截；填写原因后重新打开月份成功。 |

## 走查发现和处理

- 无课程账户的新学生错误显示冻结，已修正学籍计算及经营摘要统计；开户后刷新学生状态。
- 单节排课确认单缺学生、课程、教师和时间；手工收支确认单缺分类和备注，已补充 Core 预览字段。
- 金额和退款确认单原先显示英文键及 JSON，已改为可核对的中文字段；退款表单明确标识手续费。
- 已关账写入的预览错误原先只显示 HTTP 状态，现展示 Core 的业务冲突原因，服务端错误仍保留通用提示。
- 已重开的月份原先无法再次关账，现通过数据库条件更新支持重新关账；隔离 PostgreSQL 集成测试验证了并发重复请求仅一次成功，且保留关账、重开和重新关账的审计记录。

## 测试边界

测试与实际走查覆盖本记录列出的主路径，不代表全部权限、故障组合、移动设备及所有 AI 自然语言表达均已验收。隔离库中的测试业务数据仅供验证，未用于生产。
