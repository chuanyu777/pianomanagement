# 琴行管理系统需求设计 V2（MVP v1.1 评审稿）

> 本文继承《系统需求设计 V2（MVP v1.0）》全部未列明内容，仅记录基于 2026-10-26 新原型的业务澄清。  
> v1.0 继续保留为冻结基线；本文通过评审并完成实现验证前，不替代 v1.0。

## 1. 本版本调整范围

本版本只处理两个业务决策和一个口径冲突：

1. 学生可选联系电话；
2. 月度关账阻断项；
3. 删除“约可上 N 节”的剩余课次式展示。

AI 页面布局、导航和对话方式不改变金额、退款、工资、排课或权限规则。

## 2. 学生基本资料补充

在原 §4.2“学生”中增加：

- `phone` 为可选联系电话，保存规范化后的字符串；
- 联系电话不要求唯一，允许家庭共用号码；
- 店主可按姓名或联系电话搜索；
- 界面默认只展示脱敏号码，完整号码不进入 AI 回答、客户端日志或公开监控；
- 老师默认不能查看完整联系电话；是否展示脱敏号码仅在确认教学必要性后开放；
- 同名或同号码命中多个学生时，必须先展示候选并由用户选择，不得直接返回账户金额；
- 电话号码不是金额账户、排课冲突或学籍判定依据。

若评审决定不纳入联系电话，则应删除原型中的手机号搜索和展示，同时不得在前端保留假字段。

## 3. 月度关账检查与阻断

在原 §9 后增加“关账前检查”。关账检查由 Core 计算，前端和 Agent 不自行判断严重级别。

### 3.1 阻断项

出现以下任一项，店主不能确认关账：

- 本月已结束但仍处于待上课状态的课程；
- 有当月已完成课程但尚未生成工资记录的老师；
- 已生成但尚未支付的当月工资；
- 退款单、退款明细与退款流水不一致；
- 金额流水缺少关联记录、反向金额不匹配，或课消流水与锁定单价不一致；
- 目标月份已关账，或重开账不满足“只能重开最近一次关账月份”的限制。

阻断项必须返回检查代码、业务对象、金额或数量、来源记录和建议处理入口。

### 3.2 提醒项

以下内容仅作为店主提醒，不阻止关账：

- 欠费学生；
- 冻结学生；
- 月末后仍存在的未来待上课程；
- 不影响历史金额正确性的经营提醒。

### 3.3 准备度

“关账准备度”只能由 Core 根据固定检查项返回。检查规则未定义或服务异常时，不得展示确定百分比；应显示“无法完成检查”并保留明细。

### 3.4 关账后的工资支付

当月工资属于该月可写业务。未支付工资阻止该月关账；月份关账后不得绕过关账直接登记该月工资支付。需要纠正时，店主必须按原 §9 的最近月份重开规则处理，并保留原因。

## 4. 金额账户展示边界

删除任何“剩余课次”“约可上 N 节”作为账户事实的展示要求。MVP 继续只展示：

- 实收余额；
- 赠送余额；
- 总余额；
- 当前单节收费金额；
- 可追溯的金额流水。

前端不得用余额除以单价自行推导课次。若后续确需提供非承诺性估算，必须另立业务规则和字段，不得混入当前账户余额口径。

## 5. 实施状态与验收补充

本轮已落地并实测：

- Prisma `Student.phone` 可选字段、迁移、公开 DTO、OpenAPI 生成链路；店主可按姓名/联系电话筛选，联系电话不参与账户计算；
- Core 关账准备度读模型与关账事务前置阻断：待确认历史课程、未生成工资、未支付工资；退款/流水异常同时在 Agent 关账检查中标为阻断；
- 结构化排课、工资、手工收支、关账入口统一走浏览器 Preview → JWT Confirm → Receipt，未再从 Web 直接调用领域写入 API；
- 根级 typecheck、lint、test、build 门禁通过；数据库新增迁移已在本地 Core 数据库状态中验证为 up to date。

仍需后续单独验收：退款/流水异常的结构化修复入口、欠费/冻结/未来课程提醒的完整聚合读模型、老师端脱敏电话展示和移动端深链 E2E。本文不把这些未完成项表述为已交付。
