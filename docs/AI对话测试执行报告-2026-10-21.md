# AI对话测试执行报告

> 日期：2026-10-21。结论：不具备AI对话验收条件，不能交付为“全部功能可通过AI使用”。
> 范围：仅AI对话。本轮未运行全项目测试、构建、性能测试或手动业务页面的完整验收。

## 1. 测试结论

不是昨天、明天两种说法遗漏，而是对话实现与已冻结技术设计存在结构性偏差：业务理解依赖固定句式，多轮任务不能持续，必需的查询和基础资料预览工具缺失。

另外发现两个交付阻断问题：

1. 老师为本人已结束课程申请上课确认预览时，真实响应暴露学生实收余额、赠送余额及扣费拆分。
2. 上课确认预览在Core持久化及工作区均被标为L1；冻结需求规定它属于L2。不能只改按钮颜色。

建议先按[架构调整建议](AI对话架构调整建议-2026-10-21.md)纠正实现，再恢复完整对话验收。不是重写全部系统，也不是继续按每句话追加正则。

### 4.1 日期和业务语义

实际输入及结果：

- “今天有哪些排课？”：返回当天课表，此项局部成立，未附加工资/冻结/收入摘要。
- “查看昨天排课”“查看明天排课”：均返回“暂不支持此查询”。
- “查10月20日到22日的排课”：被当作新排课缺字段，要求重写固定命令。
- “每门课还有多少钱”“本月主课的扣费流水”“10月工资多少，怎么算”：均不能正常查询。
- “查看这个月收入”：直接选经营收入，没有按用例补问或同时区分现金收款口径；本轮未据其1.00元结果认定报表计算有误。
- 新建学生、开户、自然语序交费/赠送、按周排课、卖书收入、房租支出等首轮普遍不能到达预期任务。

### 4.2 多轮对话

真实HTTP保留相同thread仍复现：

1. “给…林悦的主课交费100元” → 提示需要渠道。
2. “支付宝” → 不支持查询，而不是补齐渠道后生成预览。

同名学生固定句式能找到两名候选，但“选择第二个”无法继续。固定句式1000元交费能生成真实Core预览；紧接“不是1000，是100，改支付宝”及“先别收了，只查余额”都无法继续。

离线另发现：强制复用同一checkpoint后，更正/取消可能沿用旧1000元/微信intent再次申请预览。**这不是本轮生产HTTP已自动入账的证据**；当前HTTP的表现是丢上下文。两种问题需同时解决，不能只改thread键。

### 4.3 教师隐私与确认风险

教师账号输入“确认对话测gbfuw林悦在2026-10-20的上课”，真实工作区返回：

| 字段 | 响应值（全部为本地合成数据） |
|---|---|
| 原实收余额 / 调整后实收余额 | 500.00 / 380.00 |
| 原赠送余额 / 调整后赠送余额 | 80.00 / 0.00 |
| 扣减实收 / 扣减赠送 | 120.00 / 80.00 |
| actionType / riskLevel | lesson.complete / L1 |

对应追加测试完整Run ID见原始JSON中的`P01-teacher-completion-ended`记录；不依赖固定Run来实现修复。

源代码核对：`LessonsService.previewComplete`产生资金display，`AssistantActionsService.createLessonMutationPreview`未按教师投影即保存和返回，同时把四种课程变更统一写成L1；Agent再按`lesson.*`统一显示L1。因此仅隐藏前端行不够，权限裁剪必须在Core返回边界完成。

教师固定句式今日课表局部可用；教师交费请求被Core以403拒绝，但对话仅得到通用失败。没有证据说明教师能执行交费，也不能把全部教师功能拒绝当成正确权限设计。
