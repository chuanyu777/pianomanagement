## 1. 用例阅读和执行说明

每条包括操作前条件、用户输入、AI应有回应、点击或故障动作、工作区内容及最终业务核对。

- “用户”是输入的自然语言；“用户动作”是选对象或点击业务确认按钮，不能把二者混为一谈。
- “AI”或“页面”是预期表现，允许措辞不同，但动作、对象、时间、金额、权限和确认步骤必须正确。
- “测试动作”由测试人员/脚本对专用环境操作，不当作用户给AI的指令。
- 查询用例不改变业务；写操作须满足方案A01–A08，每项动作分别验证，不因交费成功就推定退款、工资也安全。
- 除明确的老师用例外以店主登录。默认相关月份开放，已具必要资料和账户；特殊条件以该例为准。
- 每例使用独立初始数据与新任务；一例内连续步骤保留在同一任务中。参数变体分别执行，不能只挑最容易的一行。
- 必测变体仍有失败或阻塞时，该基础用例不能整体统计为通过；已完成的子项单独记录。
- 每例检查实际调用参数和记录ID，防止名字相同但操作错人。成功时核对原始记录、流水、状态、经办人和回执，失败时检查未产生哪些变化。
- 已确认业务功能尚未实现记失败；缺少规则或环境条件记阻塞，不能删除用例或让“不支持此查询”自动算通过。
- 涉及D01–D10的未决处理方式见全局方案第15节；不自行新增业务规则。
- Q/B/S/F/R/W/M/K/C/P/E/U只是查找用例的编号前缀，不是要求用户学习的业务术语。

## 4. 查询和经营解释测试

### Q01 查询今日经营待办

操作前条件：店主；加载今日课表、欠费、冻结、未支付工资和关账异常数据。

对话步骤：

1. 用户：今天先处理哪些事情？
2. AI：按优先级列出已结束未确认课程、欠费学生、冻结学生、待支付工资及关账前异常，并说明各项可如何处理。
3. 用户动作：点击一条已结束未确认课程。
4. AI：打开该课程的核对内容，不自动确认上课。

工作区检查：今日概况及待办卡；显示日期2026-10-21、当前角色和真实数量；每项可进入对应任务。

业务结果检查：只读查询；无课消、交费、工资支付或关账写入；首屏不等待欢迎语生成。

### Q02 用不同说法查询过去、今天和未来课表

业务结果检查：记录ID、学生、课程、老师、开始结束、状态全部匹配；昨天/明天不能落到今日摘要；每个变体独立执行。
