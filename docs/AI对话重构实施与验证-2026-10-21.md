# AI 对话重构实施与验证

日期：2026-10-21。状态：核心编排与权限改造已落地，完整 AI 功能验收尚未通过。

本文为重构阶段历史记录；后续测试入口迁移、确认恢复修复及真实模型复测结果见《AI对话重新测试报告-2026-10-21.md》，以下数字不作为最新验收结论。

本次只处理 AI 对话编排、任务交互及其 Core 权限边界，没有扩大产品范围，没有重新测试所有非 AI 业务功能，也没有提交或推送 Git。

## 1. 本次改动

### 1.1 模型理解与事实查询分开

- 生产入口从旧 `business-query-graph` 切换到 `dialogue-executor` 和新的 LangGraph。
- 模型只提出操作类型、字段及继续/更正/取消意图；结构校验失败最多修正一次。没有模型时明确不可用，不靠关键词伪装理解。
- 名称保留字母、数字和前缀。Core 的候选查询可显式启用包含搜索，精确名称优先；同名必须选择真实 ID，不擅自取第一条。
- 未访问 Core 前，模型不得宣称“查无学生”、余额或执行成功。澄清仅用于收集目标；模型自由文本不直接作为业务事实显示。
- 日期查询统一调用 Core 范围课表接口，不再从综合经营摘要拼课表。右侧只显示当前请求的结果。

### 1.2 持续任务交互

- 同一会话使用稳定 threadId，每条输入有单独 runId。补“支付宝”、追问“那明天呢”、候选选择沿用当前任务。
- 新任务清空旧金额、渠道和已选对象。更正后重新核对对象并生成新预览。
- 下一轮输入先将前一待确认预览在 Core 标记失效；不能只从页面移走卡片。
- 取消待办不撤销已经执行的业务。已执行标记跨多轮持久化，避免先取消、再更正后重复生成同笔业务。
- 原始请求保存在任务状态中；失败恢复不会把“刷新结果”当作新的业务目标。
- 候选选择绑定当前集合和任务版本，过期卡片、伪造 ID 均拒绝。
- Web 按账号、角色及教师身份隔离会话，恢复前读取当前登录身份；处理中禁用旧确认/候选按钮。
- 确认仍是浏览器携带用户 JWT 直接请求 Core，每个 previewId 使用稳定幂等键。回复生成与业务执行不再使用同一个完成文案。

### 1.3 Core 权限与预览安全

- 当前数据库身份决定操作资格。无权交费时先拒绝，不继续收集资金参数；最终读/预览/确认仍各自校验。
- 教师完成上课视图使用白名单；创建、幂等重放、历史预览、确认及回执均不向教师输出学生资金字段。
- 上课确认和撤销确认为 Core 权威 L2，Agent 不以 `lesson.*` 推断风险。
- 读取历史预览重新检查当前角色和授课归属；降权后不能读取自己过去以店主身份生成的财务预览。
- 新增内部预览失效接口与只读状态接口；已取消/失效的预览不能确认，已执行的预览不能被取消。
- Agent 会话、运行历史及 SSE 绑定 Capability 的 sub/role/teacherId/thread/run，跨身份回放拒绝。旧技术 Spike 的 approved/resume 在生产路径拒绝。

## 2. 实际实现与原技术设计的差异

当前业务流程采用“每轮有界 Graph + 持续任务快照”：

| 数据 | 实际存储与职责 |
| --- | --- |
| 单轮运行、事件、消息 | Agent 原有 PostgreSQL repository，保留租约 fencing 与 SSE 补读 |
| 业务任务上下文 | Agent 新增 `dialogue_tasks`，按 thread 串行，绑定身份并在保存前复查租约 |
| 业务预览、版本、最终执行与回执 | Core 数据库及领域服务 |

补参不是对旧 Spike 执行 `approved=true`，而是在同一 thread 提交下一轮消息。确认不进入 Agent。
官方 LangGraph checkpointer 表和原 interrupt/restart 测试未修改，但本次业务补参没有实现冻结设计中的完整 interrupt/Command(resume) 流程。
这项差异必须保留可见，不能把“任务快照可跨进程恢复”写成“业务 interrupt 已完整落地”。有限多步骤、步骤依赖和等待确认状态的完整落地仍需继续处理。

## 3. 测试环境与数据

- 本地 Docker：Core PostgreSQL 5433、Agent PostgreSQL 5434、Core 3000、单 Agent 3100、Web 5173。
- 真实模型使用用户授权的本地 DeepSeek 配置；默认无密钥测试不调用模型。密钥不进入源码、报告或镜像。
- 单元/协议测试使用隔离替身；数据库集成测试使用真实 PostgreSQL，不以替身替换数据库检查。
- Agent 完整数据库测试使用独立 `piano_agent_rework_test` 库，防止运行中的 Worker 抢走测试 Run。
- 浏览器确认使用独立的测试学生账户；只登记 10.00 元测试交费，不发生实际支付。其他模型 smoke 只申请预览，不调用确认。

## 4. 已实测结果

### 4.1 自动化与数据库

- Core 完整真实数据库测试：275/275，通过；包括失效预览不能确认、未确认不写资金、教师 L2/无资金字段、降权历史拒绝等。
- Web 测试：30/30，通过；包括连续会话、候选、确认幂等重试、处理中禁用旧卡、更正卡片状态隔离、可读回执等。
- 共享协议测试 8/8、生成 Client 测试 5/5，通过。
- typecheck、lint、build 已执行通过；lint 存在旧审计中两个未使用变量警告，Web 构建存在 chunk 体积提示。
- Agent 的完整真实数据库测试为 212 项：162 通过、50 失败、0 跳过；新对话 Graph 18 项、意图校验 3 项、身份边界 5 项、任务持久化 4 项均通过。
  50 项失败集中在三个直接调用旧 regex Graph 的审计文件；不能据此宣布新入口已通过原全量审计，也没有删除、跳过或降低这些断言。
- 根级 `npm test` 因上述 50 项失败而失败，完整门禁未全绿。最终细项以 `test-results/agent-rework-final-db-20261021.json` 为准。

### 4.2 真实模型与浏览器

真实模型最后连续两轮各 17/17 检查通过，包含真实 Agent 重启后补渠道恢复。此前复测曾发现姓名被简化、澄清中虚构“查无学生”和权限拒绝过晚；报告保留失败记录，不以最后成功轮次替代失败分析。
两轮记录为 `test-results/dialogue-rework-2026-10-21T06-07-40-254Z/results.json` 和 `test-results/dialogue-rework-2026-10-21T06-10-51-846Z/results.json`。

浏览器已走查：

1. “今天有哪些排课”→“那明天呢”，日期正确、表格无无关经营指标。
2. 发起交费缺渠道，仅补问渠道；输入“支付宝”生成真实预览。
3. 1000 元更正为 10 元并改微信；处理中旧确认按钮不可用。
4. 浏览器确认后得到 Core 回执，数据库只有一笔 10.00 元交费及一条流水。
5. 确认后再取消、再更正，均提示原业务已执行，不追加交易。
6. 刷新后恢复会话；清空开启独立任务。

模型检查原始记录：`test-results/dialogue-rework-*/results.json`。它们包含测试业务内容，不包含登录密码、JWT 或模型密钥。
