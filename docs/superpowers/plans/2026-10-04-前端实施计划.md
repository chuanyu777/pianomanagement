- `src/data-provider.ts` 自定义 provider：**唯一**和后端对接的地方。
  列表统一 `Paginated<T>`；额外查询参数（period、studentId…）通过 `meta: { query: {...} }` 传；
  报表类用 `useCustom({ url: '/overview?period=2026-10', method: 'get' })`。
- `src/auth-provider.ts` JWT 登录；401 自动登出。`getToken()` / `getCurrentUser()`（含 role）从这里拿。
- `src/period.ts` 前端月份工具。**前端不做业务算术**（金额、剩余课时、比例都以后端返回为准）。
- `src/App.tsx` 已把 14 个模块的**路由和菜单全部接好**。**不要改 App.tsx** —— 你只改自己页面目录里的文件。
- 登录页、首次引导页、经营总览页、课程类型列表页已写完。

## 写法模板（照抄 `src/pages/course-types/list.tsx`）
- 列表：`List` + `useTable<T>({ resource, sorters })` + `Table.Column`
- 新增/编辑：本地 state 控制一个 `Modal`，`Form` + `useCreate` / `useUpdate`，**保存后关弹窗并让表格自动刷新**
- 删除：`DeleteButton`（自带确认）
- 每页顶部给一句中文说明（需求里的业务口径，让用的人不用猜）

## 硬规则（同 AGENTS.md，外加这几条）
1. 只改你负责的页面目录。**App.tsx、data-provider、auth-provider、period.ts 一律不许动。**
2. 金额一律显示后端返回的字符串（两位小数），**不要在前端做加减乘除**；
   比例（如 0.1500）显示成百分比是允许的展示转换。
3. 你要做的是**替换占位组件**：`src/pages/<模块>/page.tsx` 里现在是
   `Empty description="xxx 页面待实现"`，把它整个换掉，导出的组件名和文件名保持不变。
   做完的页面里**不允许再出现「待实现」**。
4. 接口路径看 `apps/api/src/modules/*/xxx.controller.ts`（`@Controller('xxx')` + 方法上的路径），
   **以控制器为准，不要猜**。请求统一走 `useList/useTable/useCustom/useCreate/useUpdate`，
   不要自己 fetch（bootstrap 页是历史例外）。
5. 权限：后端已按角色把守。教师可见的页面（沉睡名单、自己的工资）不要在前端再判断角色；
   店主专属页面在 403 时会弹通知，够用。
6. 每改完一个页面就 `npx tsc --noEmit`（在 apps/web 下）确认，不许攒到最后。

## 各页要做什么（接口路径已核实）
- **teachers / students / items / users**：标准 CRUD 列表（照模板）。users 列表只读+停用开关，不要提供删除。
- **enrollments**：列表 + 新增（学生/老师/课程三个下拉，选项来自各自列表接口）+ 编辑单价。
- **lessons**：列表（可按老师/日期筛选）+ 新增排课（Modal，选学生+老师+课程，service 自动定位报名关系）
  + 行操作「确认 / 请假 / 取消」，每个动作先 `Modal.confirm`。
- **ledger**：选学生 → 展示各课程实收/赠送余额、剩余课时、流水表（按月份筛选）。
- **finance**：收入表 + 支出表（月份选择器）+ 其它支出/手工补录的新增编辑。
- **payroll**：月份选择器 + 工资表（每人一行，含业绩/课消奖/应发/实发/代扣）+ 底部合计 + 编辑基础项。
- **analytics**：教师业绩排行、学生消费排行（表格，rank 服务端已排好）。
- **risks**：欠费名单 + 沉睡名单（分 sleeping / never 两类展示，阈值 40 天要展示出来）。
- **onboarding**：8 步状态 + 「完成初始化」按钮 + 接续数据表单。
