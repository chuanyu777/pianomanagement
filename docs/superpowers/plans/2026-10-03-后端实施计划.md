## 0. 已定的口径（有歧义的地方，按这里，不要再自己解释）

需求里没写死、但必须统一的地方：

| 问题 | 定为 |
|---|---|
| 收入项清单里的「钢琴/听力/基本功/集训/书」 | 它们是**交费时选择的收入项**。交费流水带 `incomeItemId`，收入表按收入项汇总交费金额 |
| 「交费现金」这一行 | **不单独成行**，避免和上面的收入项重复计数；收入小计(现金) = Σ各收入项交费 + 退费手续费 |

| 退费 | 属**现金支出**（实退金额），经营口径为 0 |

| 「流失学生」 | = `Student.status = WITHDRAWN` 或 `wantsRefund = true` |

| 「按月」的月份表示 | 统一 `YYYY-MM` 字符串，工具函数在 `src/common/period.ts` |

## 1. 余额口径（US-ML-01 / US-ML-02）—— 全系统最核心的不变量

**余额不存储，只计算。** `Enrollment` 存起始值，之后每一笔变动都是 `LedgerEntry` 上的
带符号 `paidDelta` / `giftDelta`。**任何地方都不许再存一份「当前余额」字段。**

```
单条报名关系(Enrollment)：
  paidBalance = initialPaidBalance + SUM(paidDelta)
  giftBalance = initialGiftBalance + SUM(giftDelta)
  totalBalance = paidBalance + giftBalance        // 负数 ⇒ 该学生欠费

学生维度：paidBalance/giftBalance = 其各 Enrollment 之和
预计剩余课时 = totalBalance ÷ Enrollment.unitPrice   // unitPrice 为 0 时不展示，提示先维护单价
```

唯一权威实现：`src/modules/ledger/balance.ts` 的 `computeEnrollmentBalances()`。
**其它模块一律调用它，不许自己写 SUM。**

## 2. 消费与回冲（US-CC-03）

**非赠送课**确认：
- `consumption = Lesson.unitPriceSnapshot`（确认时锁定的快照，此后改价不影响历史）
- 按 `Organization.consumptionOrder` 扣：`GIFT_FIRST` 先扣赠送池扣到 0，余下扣实收池；
  `PAID_FIRST` 反之。**允许扣成负数**（欠费是合法状态）
- 写一条 `LedgerEntry`：`kind = CONSUMPTION`，`lessonId`，`occurredAt = 确认时间`

**赠送课**确认：
- 必须指定 `Lesson.giftGrantId`，且该赠送额度未撤销、未用满
- 扣减金额 = 该 `GiftGrant.unitPrice`（**赠送时的快照**，不受后续改价影响）
- 写 `LedgerEntry`：`kind = CONSUMPTION`，`giftDelta = -unitPrice`，`paidDelta = 0`，`lessonId`
- **不计入老师业绩、不计入课时消费收入**

**取消 / 请假**：
- 若该课**曾确认过**：追加一条 `CONSUMPTION_REVERSAL`，delta 取原条目的相反数，
  `reversesEntryId` 指向原条目。**绝不 UPDATE 原条目。**
- 若从未确认：不产生任何流水
- 已确认的课**不允许直接改回排课状态**（US-SC-02）

`LedgerEntry.reversesEntryId` 上有唯一约束 —— 同一笔只能被回冲一次，
这是「同一节课重复确认不应重复扣减」的数据库层兜底。

**课时归属月份 = `Lesson.confirmedAt` 所在月。**

## 3. 赠送（US-GL-01/02/03）

- 折算单价取该 Enrollment 当前 `unitPrice`；`amount = lessons × unitPrice`
- 入池：`LedgerEntry{ kind: GIFT, giftDelta: +amount, giftGrantId }`
- **赠课成本 = 赠送当月一次性计入经营支出**（不是按上课月摊销）
- 撤销：`LedgerEntry{ kind: GIFT_REVOKE, giftDelta: -amount }` + 赠课成本随之冲回；
  已有已确认的赠送课则**拒绝撤销**
- 额度占用 = 该 Grant 下 `status = CONFIRMED` 的 Lesson 条数
  `remaining = lessons - 已确认条数`，用**算**的，不存字段

## 4. 退费（US-RF-02/03）

```
paidTotal = Σ 该学生各 Enrollment 的 paidBalance
giftTotal = Σ 该学生各 Enrollment 的 giftBalance
feeAmount = paidTotal × feeRate        // feeRate 逐笔可覆盖，默认取机构设置
refundAmount = paidTotal - feeAmount
```
- `mode = REFUND`：给每条 Enrollment 写 `LedgerEntry{ kind: REFUND, paidDelta: -paidBalance, giftDelta: -giftBalance }`，
  学生状态 → `WITHDRAWN`；手续费计入收入项「退费手续费」
- `mode = KEEP`：**不写流水**，两池原样保留，学生状态 → `PAUSED`
- 两种模式都写一条 `RefundRecord`

## 5. 收支（US-IE-01/02/03/04）

**收入表**（按 `period`）每行：`itemId, name, isAuto, cashAmount, consumptionAmount, ytdAmount`
- 交费类收入项（`autoSource = null`）：`cashAmount = Σ LedgerEntry(kind=PAYMENT, incomeItemId=该项)` 当月
- `LESSON_CONSUMPTION`：`consumptionAmount = Σ 非赠送已确认课 unitPriceSnapshot` 当月；`cashAmount = 0`
- `REFUND_FEE`：`cashAmount = Σ RefundRecord.feeAmount` 当月
- 手工补录 `ManualIncome` 叠加到对应收入项的 `cashAmount`

**支出表**（按 `period`）每行：`itemId, name, isAuto, cashAmount, operatingAmount, ytdAmount`
- `PAYROLL_ACCRUED`（工资行）：`operatingAmount = 本月应发工资合计`；`cashAmount = 上月应发合计`
  （**同一行两个口径的值不同，这是需求要的「两口径相差一个月」**）
- `PAYROLL_CASH`：若清单里另建了这一项，取上月应发；否则并入工资行（默认模板只建一个工资行）
- `GIFT_COST`：`operatingAmount = 当月赠送折算金额合计`；`cashAmount = 0`
- `PROFIT_SHARE`：`cashAmount = 上月盈利合计 × 机构利润分配比例合计(=100%)`，即 = 上月盈利；`operatingAmount = 0`
- `REFUND_PAID`：`cashAmount = Σ RefundRecord.refundAmount` 当月；`operatingAmount = 0`
- 普通支出项：`cashAmount = operatingAmount = Σ OtherExpense(该项, 当月)`

**小计与结余**
```
收入小计(cash)        = Σ 收入行 cashAmount
收入小计(consumption) = Σ 收入行 consumptionAmount
支出小计(cash)        = Σ 支出行 cashAmount
支出小计(operating)   = Σ 支出行 operatingAmount
现金结余 = 期初现金 + Σ现金收入 − Σ现金支出      // 期初现金 = Organization.initialCashBalance
盈利     = 收入小计(consumption) − 支出小计(operating)
```
**「上月」= period 的前一个月。首月没有上期 → 取 `Organization.previousMonthProfit` / `previousMonthPayroll`。**

## 6. 工资（US-PR-01…07）

```
业绩(teacher, period)   = Σ 该老师该月 CONFIRMED 且 !isGift 的 Lesson.unitPriceSnapshot
课消奖                   = 业绩 × (Payroll.commissionRate ?? Teacher.commissionRate ?? Organization.defaultCommissionRate)
应发综合工资             = baseSalary + pianoBonus + recruitBonus + 课消奖
实发工资                 = 应发 − Σ PayrollDeduction.amount
```
**业绩与课消奖一律实时汇总，不落库。** 存一份就会和上课确认对不上。
`Payroll` 只存人工录入的部分（出勤、基本工资、钢琴奖、招生奖、代扣）。

老师看自己（US-PR-07）：`TEACHER` 只能取 `teacherId = 自己关联的老师` 的那条，
没关联老师就直接 403。**服务端强制，不能只靠前端不显示。**

## 7. 关账（US-PC-01/02）

- `ClosedPeriod.period` 记录已锁定月份
- **任何会写台账 / 收支 / 工资的入口**都要先过 `assertPeriodOpen(period)`：
  命中已锁月份 → 409。锁定前那次写入的 `occurredAt` 决定它属于哪个月
- 反关账只允许 `OWNER`（`@Roles(UserRole.OWNER)`）
- 关账本身不是「结算」——它不产生任何金额，只是禁止改动

## 12. 跨模块接口契约（**并行开发的唯一共识，必须一字不差地实现**）

别人要从你的模块拿数据，只能调下面这些函数。签名不许改、语义不许改。
金额对外一律序列化成**两位小数字符串**（`toMoneyString`）。

```ts
// ── modules/ledger/balance.ts（已完成，直接用，不要改） ──────────────
computeEnrollmentBalances(prisma, enrollmentIds: string[]): Promise<Map<string, EnrollmentBalance>>
// EnrollmentBalance = { enrollmentId, paid: Decimal, gift: Decimal, total: Decimal }
splitConsumption(order, amount, paidBalance, giftBalance): { paidDelta: Decimal; giftDelta: Decimal }

//                若 period 的上一个月没有工资数据（首月）→ 取 Organization.previousMonthPayroll

**谁依赖谁**（照这个顺序，不要反向 import）：

```

        ↓
course-types / teachers / students / enrollments / items
        ↓

- `finance` 与 `payroll`：finance 只 import `PayrollService` 的 `computePeriodTotals`，
  payroll **绝不** import finance。
