# 琴行管理系统需求设计 V2（MVP v1.0）

> 状态：已冻结并归档。  
> 版本：v1.0  
> 冻结日期：2026-10-14  
> 定位：重构后的产品需求基线，不以旧代码结构为前提。

## 1. 产品目标

为单个琴行提供一套最小可用的经营系统，优先解决四件事：

1. 清楚记录每个学生在不同课程下的实收金额和赠送金额。
2. 完成排课、调课、取消和上课确认。
3. 上课确认后准确扣减对应课程金额，并保留完整流水。
4. 学生退学时按课程登记退款，月底后历史金额不被随意改动。

MVP 采用“按课程隔离的金额账户”，不采用课包、剩余课次或购买批次模型。

## 2. MVP 范围

### 2.1 本期必须实现

- 店主和老师账号登录。
- 老师、学生、课程基础资料。
- 学生课程账户及学生个性化单节收费金额。
- 按课程登记交费和赠送金额。
- 逐节排课、按周批量排课、调课、取消、上课确认、错误确认撤销。
- 实收余额、赠送余额及不可变金额流水。
- 在读、冻结、退学三种学籍展示。
- 最终退学退款登记。
- 轻量月度关账。
- 简化工资核算和工资支付登记。
- 学生课程余额、课程消费、现金收支和经营利润基础查询。

### 2.2 本期明确不做

- 课包、剩余课次数、课包有效期。
- 多校区、多机构、多币种。
- 小组课、教室和琴房管理。
- 自动循环排课。
- 线上退费申请、审批和银行付款。
- 只退部分课程后继续在读。
- 学生或家长自助端。
- 复杂工作流和多级审批。
- 除店主、老师之外的细分岗位。
- 工资分批支付。
- 利润自动分配、股东账户和分红付款。
- 复杂趋势、排行榜和自定义报表。

## 3. 角色

| 角色 | MVP 权限 |
|---|---|
| 店主 | 维护全部资料，登记交费、赠送、退款、工资和手工收支，排课，确认或撤销上课，查看金额流水和报表，执行关账。 |
| 老师 | 查看自己的课表和必要的学生教学信息；调课、取消、确认自己的课程；不得查看学生余额、交费和退款。 |

老师只能看到自己负责的排课和学生，不得看到其他老师的数据。

## 4. 核心业务对象

### 4.1 课程

每种课程包含：

- 名称；
- 默认单节收费金额；
- 默认单节时长，单位为分钟；
- 启用状态。

不同课程可以有不同收费金额和时长。例如主课 60 分钟，陪练 45 分钟。

MVP 中单节排课默认使用课程时长，不支持为某一节课单独修改时长。

### 4.2 学生

学生包含基本资料和退学状态。学生可同时开通多个课程账户。

### 4.3 学生课程账户

学生和课程唯一确定一个课程账户：

```text
学生 + 课程 = 学生课程账户
```

账户包含：

- 学生；
- 课程；
- 该学生当前单节收费金额。

同一种课程允许不同学生使用不同单节收费金额。课程默认价只用于创建账户时填充默认值，
店主可以为学生修改。

课程账户不绑定老师。老师由每一节排课单独记录，换老师不转移余额。

### 4.4 课程金额流水

课程账户维护两个逻辑金额池：

- 实收余额；
- 赠送余额。

余额不直接修改，统一由流水计算：

```text
实收余额 = 期初实收 + 交费 − 实收课消 − 实收退款 + 实收冲正
赠送余额 = 期初赠送 + 赠送 − 赠送课消 − 赠送清零 + 赠送冲正
```

每条流水至少记录：

- 学生课程账户；
- 流水类型；
- 实收金额变动；
- 赠送金额变动；
- 业务发生时间；
- 关联的排课、交费、赠送或退款记录；
- 经办人；
- 备注。

流水写入后不得编辑或删除，错误通过反向流水纠正。

## 5. 金额规则

### 5.1 交费

1. 交费必须指定学生和课程。
2. 一笔交费只能进入一个课程账户；一次实际收款涉及多门课程时，分别登记各课程金额。
3. 交费金额必须大于零。
4. 交费进入该课程的实收余额。
5. 交费记录保存发生时间、金额、经办人和备注。
6. 错误交费不得直接修改，通过等额反向流水冲正后重新登记。

### 5.2 赠送

1. 赠送必须指定学生和课程。
2. 赠送的是金额，不记录赠送课次。
3. 赠送金额必须大于零。
4. 赠送进入该课程的赠送余额。
5. 赠送余额固定优先于实收余额扣除，不提供扣费顺序设置。
6. 未发生消费的错误赠送可冲正；已发生消费时仍通过反向流水处理，不能删除历史。

### 5.3 上课扣费

确认上课时，系统锁定学生课程账户当时的单节收费金额，并按以下顺序扣费：

1. 先扣赠送余额；
2. 赠送余额不足的部分扣实收余额；
3. 两者不足时，剩余部分计入实收余额负数，形成欠费。

示例：

```text
单节收费：200 元
确认前：赠送余额 80 元，实收余额 500 元
确认后：赠送余额 0 元，实收余额 380 元
```

学生单节收费金额修改后，只影响以后确认的课程；历史课程继续使用当时锁定的金额。

### 5.4 收付款渠道

交费、退款、工资支付和手工收支必须记录收付款渠道。MVP 固定提供：

- 现金；
- 微信；
- 支付宝；
- 银行卡；
- 其他。

选择“其他”时必须填写备注。渠道只用于查询和对账，不改变金额计算规则。

## 6. 排课

### 6.1 排课内容

每节排课包含：

- 学生；
- 课程；
- 老师；
- 开始时间；
- 结束时间，按课程默认时长计算；
- 状态；
- 备注。

排课前必须确认学生已经开通对应课程账户。

### 6.2 时间冲突

同一老师的两节有效排课时间区间不得重叠。

```text
已有课程：[09:00, 10:00)
新课程：[09:45, 10:30)
结果：冲突，不能保存
```

已取消课程不参与冲突判断。

### 6.3 排课状态

MVP 只保留：

| 状态 | 含义 |
|---|---|
| 待上课 | 已创建但尚未确认完成。 |
| 已完成 | 已确认上课并完成扣费。 |
| 已取消 | 学生请假、老师请假或其它原因导致本节不再进行，不扣费。 |

不再单独设置“请假”状态。请假操作等同于取消待上课记录，可在备注中记录原因。

### 6.4 操作规则

- 调课：仅修改待上课记录的开始时间，修改后重新检查冲突。
- 取消：待上课记录可取消，取消后不扣费。
- 确认：只有当前时间已经达到课程结束时间，待上课记录才可确认；老师和店主遵守相同限制。确认后立即追加消费流水。
- 已完成课程不能普通取消或调课。
- 错误确认：店主可执行“撤销确认”，系统追加等额反向流水，并将课程恢复为待上课；老师无权执行。
- 同一课程不得重复确认或重复撤销。

### 6.5 按周批量排课

店主可以一次生成多周固定课程，录入：

- 学生；
- 课程；
- 老师；
- 首次上课时间；
- 生成周数。

系统按课程默认时长、每隔七天生成一节独立排课。生成后每节课都可单独调课或取消，
后续不会自动继续生成新排课。

保存前检查整批课程以及现有排课的老师时间冲突。任一节发生冲突时，整批不保存，并明确显示冲突日期和时间。

## 7. 学籍状态

系统只展示三种学籍状态：

| 状态 | 判定 |
|---|---|
| 在读 | 未退学，且距离最近一次已完成课程不超过 31 天。 |
| 冻结 | 未退学，连续超过 31 天没有完成任何课程。 |
| 退学 | 已完成最终退款登记。 |

判定细则：

1. 在读和冻结由系统动态计算，不由人工直接修改。
2. 已有上课记录的学生，从最后一次已完成课程的时间开始计算。
3. 从未完成课程的学生，从第一个课程账户的系统创建时间开始计算；该时间由系统记录，不需要人工填写。
4. 第 31 天仍为在读，超过 31×24 小时后显示冻结。
5. 冻结学生再次完成课程后自动显示为在读。
6. 退学状态优先级最高，不再参与在读/冻结计算。

## 8. 最终退学退款

### 8.1 使用范围

1. 退款申请、审批和实际付款在线下完成。
2. 系统只登记最终退款结果。
3. MVP 只支持最终退学退款，不支持只退一门课程后继续在读。

### 8.2 退款明细

一次退款登记包含一张退款单和多条课程退款明细。

每条课程明细记录：

- 课程；
- 退款前实收余额；
- 退款前赠送余额；
- 该课程实收退款金额；
- 该课程赠送清零金额。

规则：

1. 各课程分别计算，不跨课程抵扣。
2. 只退正数实收余额，赠送余额不退款。
3. 实收余额为负的课程必须先处理欠费，不能用其它课程余额抵扣。
4. 退款完成后，所有课程的实收余额和赠送余额都必须为零。
5. 退款明细和清零流水必须在一次提交中完成。
6. 退款成功后学生状态变为退学。

### 8.3 手续费

1. 手续费按整笔退款录入一个固定金额，不按比例输入。
2. 手续费必须大于等于零，且不得超过各课程实收退款金额合计。
3. 实际退款总额计算如下：

   ```text
   应退实收合计 = Σ 各课程实收退款金额
   实际退款总额 = 应退实收合计 − 手续费固定金额
   手续费比例   = 手续费固定金额 ÷ 应退实收合计 × 100%
   ```

4. 手续费比例仅用于显示，保留两位小数，不参与金额计算。
5. 应退实收合计为零时，手续费必须为零，手续费比例显示为 `0.00%`。

示例：

```text
主课实收退款：1,000 元
陪练实收退款：500 元
手续费：100 元
实际退款：1,400 元
手续费比例：6.67%
```

## 9. 月度关账

MVP 保留轻量关账，用于防止历史经营数据被误改。

1. 仅店主可以关账。
2. 关账后不得向该月新增、修改或删除交费、赠送、课消、退款、工资、手工收支及其它金额记录。
3. 已关账月份的历史记录继续保留，不因后续课程状态变化而重新计算。
4. 发现历史金额错误时，优先在当前开放月份追加冲正流水。
5. 只允许撤销最近一次关账；撤销时必须填写原因。
6. 已存在更晚关账月份时，不得重开更早月份。
7. 关账不生成新的金额，只锁定业务写入。

报表必须基于金额流水统计，不能仅根据课程当前状态重新计算历史月份。

## 10. 工资

### 10.1 老师工资配置

每位老师配置：

- 默认基本工资；
- 默认课消提成比例。

生成某月工资时复制当时的默认值。店主可以在该月关账前修改该月使用的基本工资和提成比例，
但修改老师默认配置不得影响已经生成的历史月份。

### 10.2 月度工资计算

老师课程业绩按该老师当月已完成课程的锁定扣费金额合计计算：

```text
课程业绩 = Σ 当月已完成课程的锁定单节收费金额
课消提成 = 课程业绩 × 当月提成比例
应发工资 = 当月基本工资 + 课消提成 + 手工奖金
实发工资 = 应发工资 − 手工代扣
```

规则：

1. 无论课程实际从赠送余额还是实收余额扣除，均按完整的锁定收费金额计入老师课程业绩。
2. 赠送属于琴行营销成本，不减少老师业绩和提成。
3. 手工奖金和手工代扣必须大于等于零，并填写备注。
4. 实发工资不得小于零。
5. MVP 不加入考勤天数、迟到次数等未参与公式的字段。

### 10.3 工资支付

1. 月度工资只有“未支付”和“已支付”两种状态。
2. 店主登记支付时记录支付日期；现金报表按实际支付日期计入工资支出。
3. MVP 不支持一笔工资分多次支付；如登记错误，通过取消支付后重新登记纠正。
4. 已关账月份的工资计算结果不得修改；后续发现错误时在当前开放月份登记工资调整。

## 11. 基础查询与报表

MVP 至少提供：

1. 学生课程账户列表：每门课程的实收、赠送、总余额和当前单节收费金额。
2. 学生金额流水：按课程、类型和日期筛选。
3. 老师课表：待上课、已完成、已取消课程。
4. 月度课程消费：按课程、老师和学生汇总已确认消费金额。
5. 老师月度业绩与工资：课程业绩、提成、奖金、代扣、应发、实发及支付状态。
6. 月度现金收支：交费、实际退款、已支付工资和手工现金收支。
7. 月度经营结果：课消收入、工资成本、赠送成本、手工经营支出和经营利润。
8. 欠费名单：任一课程实收余额为负的未退学学生。
9. 冻结学生名单：动态状态为冻结的学生，老师只能查看自己的学生。

### 11.1 现金收支口径

现金报表按实际收付款日期统计：

```text
现金收入 = 学生交费 + 书籍销售 + 钢琴/乐器销售 + 外部合作收入 + 其他收入
现金支出 = 实际退款 + 已支付工资 + 手工现金支出
现金净额 = 现金收入 − 现金支出
```

退款手续费是从应退金额中留存的部分，不是一次新的收款，因此只在退款明细中单独展示，
不重复计入现金收入。实际退款已经等于应退实收合计减手续费。

### 11.2 经营结果口径

经营报表按业务归属月份统计：

```text
课消收入 = 当月已完成课程的锁定扣费金额合计
经营收入 = 课消收入 + 退款手续费 + 书籍销售 + 钢琴/乐器销售 + 外部合作收入 + 其他收入
经营支出 = 当月应发工资 + 当月赠送金额 + 手工经营支出
经营利润 = 经营收入 − 经营支出
```

规则：

1. 从赠送余额扣除的课程仍按完整金额计入课消收入。
2. 赠送金额在发放当月一次性计入营销成本，不在后续消费时再次计入成本。
3. 工资按应发工资所属月份计入经营支出，是否已经支付不改变经营口径。
4. 退款手续费在退款登记当月计入经营收入，但不作为一笔新的现金收入。
5. 本期所有手工收入和手工支出都属于经营收支，不设置“计入经营”开关。
6. 本期仅计算经营利润，不执行利润分配。

### 11.3 手工收支分类

手工收入只允许使用以下固定分类：

- 书籍销售；
- 钢琴/乐器销售；
- 外部合作收入；
- 其他收入。

退款手续费由退款登记自动产生，不允许通过手工收入重复登记。学生交费也必须从交费入口登记。

手工支出只允许使用以下固定分类：

- 房租物业；
- 水电网络；
- 市场推广；
- 办公耗材；
- 维修维护；
- 书籍采购成本；
- 钢琴/乐器采购成本；
- 外部合作成本；
- 其他支出。

每笔手工收支记录发生日期、分类、金额、收付款渠道、经办人和备注。金额必须大于零。
MVP 不管理商品、库存、采购批次和单笔销售毛利；销售收入与相关采购成本分别登记。

复杂趋势、排行榜、利润分配和自定义报表不作为本轮核心 MVP 的验收条件。

## 12. 核心验收场景

### 12.1 课程金额隔离

```text
已知：小明主课实收 1,000 元，陪练实收 500 元
当：确认一节收费 200 元的主课
则：主课实收变为 800 元，陪练仍为 500 元
```

### 12.2 赠送优先

```text
已知：主课赠送 80 元，实收 500 元，单节收费 200 元
当：确认一节主课
则：赠送余额为 0 元，实收余额为 380 元
```

### 12.3 个性化单价与历史价格

```text
已知：小明主课单价 200 元，并已确认一节课
当：店主把小明主课单价调整为 220 元，再确认下一节课
则：第一节仍消费 200 元，第二节消费 220 元
```

### 12.4 换老师不转余额

```text
已知：小明主课余额 1,000 元，上一节由王老师授课
当：下一节改由李老师授课并确认
则：仍从小明同一个主课账户扣费，历史课程分别保留各自老师
```

### 12.5 调课与取消

```text
已知：一节待上课课程安排在周一 09:00
当：调课至周二 10:00
则：只修改排课时间，不产生金额流水

当：取消该待上课课程
则：状态变为已取消，不产生金额流水
```

### 12.6 最终退款

```text
已知：主课实收 1,000、赠送 200；陪练实收 500、赠送 100
当：登记最终退款，手续费固定为 100 元
则：应退实收 1,500 元，实际退款 1,400 元，手续费比例显示 6.67%
且：四个余额全部清零，学生状态变为退学
```

### 12.7 冻结状态

```text
已知：学生最后一次完成课程距当前时间正好 31 天
则：状态为在读

已知：学生最后一次完成课程距当前时间超过 31 天
则：状态为冻结
```

### 12.8 关账后纠错

```text
已知：10 月已经关账
当：11 月发现 10 月某节课扣费错误
则：10 月原流水不变，在 11 月追加反向流水和正确流水
```

### 12.9 赠送扣费与老师业绩

```text
已知：一节课程锁定收费 200 元，其中赠送余额扣除 80 元、实收余额扣除 120 元
当：计算该老师当月课程业绩
则：该节课程按 200 元计入课程业绩
```

### 12.10 现金与经营口径

```text
已知：本月交费 1,500 元；退款应退 1,500 元、手续费 100 元、实际退款 1,400 元
则：现金收入为 1,500 元，现金支出为 1,400 元，现金净额为 100 元
且：手续费在退款明细中显示，但不作为第二笔现金收入重复统计
```

## 13. 已确认的产品决策

| 决策 | 结果 |
|---|---|
| 收费模型 | 金额账户，不使用课包。 |
| 金额隔离 | 按学生、课程分开。 |
| 学生价格 | 同一课程允许不同学生使用不同单节收费金额。 |
| 赠送形式 | 赠送指定课程的金额。 |
| 扣费顺序 | 固定赠送优先。 |
| 课程时长 | 不同课程配置不同默认时长。 |
| 调课 | 修改待上课排课时间。 |
| 请假 | 等同于取消待上课排课。 |
| 学籍 | 在读、冻结、退学。 |
| 冻结阈值 | 超过 31 天没有完成课程。 |
| 退款范围 | 最终退学退款，各课程分别登记。 |
| 手续费 | 输入固定金额，同时显示换算百分比。 |
| 关账策略 | 保留轻量关账，历史错误优先在当前月份冲正。 |
| 老师业绩 | 按已完成课程的完整锁定收费金额计算，赠送扣费不减少业绩。 |
| 工资 | 基本工资 + 课消提成 + 手工奖金 − 手工代扣。 |
| 报表口径 | 同时提供现金收支和经营结果两种基础报表。 |
| 利润分配 | 不进入 MVP，线下处理。 |
| 其它业务收入 | 书籍销售、钢琴/乐器销售、外部合作收入和其他收入。 |
| 退款手续费 | 计入经营收入，但不重复计入现金收入。 |
| 销售成本 | 手工登记采购成本，不建设商品和库存系统。 |
| 批量排课 | 支持按周批量生成；生成后每节独立，冲突时整批不保存。 |
| 上课确认时点 | 老师和店主均只能在课程结束后确认。 |
| 收付款渠道 | 现金、微信、支付宝、银行卡、其他；选择其他时备注必填。 |
