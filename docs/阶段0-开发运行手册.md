# 阶段 0 开发运行手册

本手册只覆盖 AI Native MVP 的阶段 0 技术 Spike。当前目标是验证 Core、Agent Runtime、Web、双数据库、
Capability、SSE 和 LangGraph 的基础边界；不接真实资金写入。冻结业务需求仍以
`系统需求设计-V2-MVP-v1.0.md` 和 `系统需求设计-AI-Native-MVP-v1.0.md` 为唯一基线，
本手册不新增业务规则。

状态口径：本手册把“代码已存在”“本次已实测”和“待验收”分开记录。没有实测证据的内容不能写成已完成。

## 1. 启动顺序

在仓库根目录执行：

```bash
npm install
```

首次运行还要创建两个未提交的本地环境文件：

```bash
cp apps/core-api/.env.example apps/core-api/.env
cp apps/agent-runtime/.env.example apps/agent-runtime/.env
```

按第 2 节填写变量。`.env` 不得提交，也不要把私钥、服务密钥、模型密钥或完整连接串粘贴到对话、日志或截图中。

启动两个本地 PostgreSQL 16：

```bash
npm run db:up
```

约定端口：

- Core PostgreSQL：`localhost:5433`
- Agent PostgreSQL：`localhost:5434`

初始化 Core 数据库和 Prisma Client：

```bash
npm run db:generate
npm run db:migrate
```

初始化 Agent Runtime 自己的 Run/Message/Event 业务元数据表（与 LangGraph 官方检查点表分开）：

```bash
npm run agent:db:migrate
```

初始化 Agent 数据库的 LangGraph 检查点表。该步骤必须显式执行一次，不能藏在服务启动钩子中：

```bash
npm run agent:checkpoint:setup
```

该命令使用官方 `@langchain/langgraph-checkpoint-postgres` 的 `PostgresSaver.setup()`，只连接 Agent PostgreSQL（5434），并记录所使用的版本。不得使用自定义 Prisma checkpointer，也不得连接 Core PostgreSQL。

然后按顺序启动服务：

```bash
npm run dev:core
npm run dev:agent
npm run dev:web
```

浏览器只应访问 Web 和 Core 的公共接口。浏览器不能直连 Agent Runtime；未来由 Core Gateway 转发会话/SSE，并向 Agent 签发短期 Capability。当前 Web 已接通 `/api/assistant/status`，可显示 Core 数据库与 Agent Runtime 的可用性，但公开登录、JWT/角色鉴权和 Assistant Run Controller 尚未实现，因此会话仍处于未接通/结构化降级状态。确认操作必须由浏览器携带用户登录态直接调用 Core；阶段 0 尚无可确认的业务写入接口。

## 2. 环境变量

本地环境变量分别放在各服务自己的未提交 `.env` 文件中。`.env` 不进 Git，任何生产连接串、私钥、模型密钥都不得写入文档、日志或命令输出。

Core API：

```text
CORE_DATABASE_URL=<local-core-postgres-url-on-5433>
CORE_PORT=3000
AGENT_RUNTIME_URL=http://localhost:3100
CAPABILITY_SIGNING_PRIVATE_KEY_B64=<base64-encoded-local-ed25519-pkcs8-key>
INTERNAL_SERVICE_SECRET=<same-local-secret-as-agent-minimum-32-chars>
AGENT_REQUEST_TIMEOUT_MS=15000
AGENT_STREAM_IDLE_TIMEOUT_MS=30000
AGENT_STATUS_TIMEOUT_MS=2000
```

Agent Runtime：

```text
AI_ENABLED=false
AI_PROVIDER=<selected-provider>
AI_MODEL=<selected-model>
AI_API_KEY=<local-model-key-not-committed>
AGENT_DATABASE_URL=<local-agent-postgres-url-on-5434>
CORE_INTERNAL_API_URL=http://localhost:3000/api/internal
INTERNAL_SERVICE_SECRET=<same-local-secret-as-core-minimum-32-chars>
AI_REQUEST_TIMEOUT_MS=15000
AI_RUN_TIMEOUT_MS=60000
AI_MAX_STEPS=<small-positive-integer>
AI_MAX_TOOL_CALLS=<small-positive-integer>
AI_MAX_OUTPUT_TOKENS=<small-positive-integer>
AI_TRACING_ENABLED=false
```

阶段0默认 `AI_ENABLED=false`，用于无密钥安装、编译、单元测试和结构化降级验证。只有在已选择供应商、配置本地密钥并显式打开开关后，才运行 Live Model 测试；供应商、模型和数据区域仍按技术设计的部署决策确认。

所有变量都必须由对应服务在启动时校验。Core 没有模型密钥；Agent 没有 Core 数据库凭证。
当前 Agent 不读取或验证单独的 `CAPABILITY_VERIFY_PUBLIC_KEY`；服务间使用同一密钥生成带时间戳与 nonce 的 HMAC，并携带 Capability Header，
随后由 Agent 调用的 Core Internal API 验证 Capability 签名、权限及 `threadId/runId`。不要在环境文件中添加一个
文档未实现的公钥变量来掩盖这个边界。

## 3. 生成 OpenAPI Client（阶段 0 已接通）

Core OpenAPI 导出和类型化 Client 生成链路已经存在，使用顺序如下：

```bash
npm run openapi:export -w @piano/core-api
npm run generate -w @piano/generated-core-client -- \
  --input ../../apps/core-api/openapi.json
```

`apps/core-api/openapi.json` 和 `packages/generated-core-client/src/generated/` 都是生成物，
不手工编辑、不提交。当前规范只覆盖阶段 0 的健康检查、内部工具和技术 Preview，不代表领域 API 已完成。

## 4. 阶段0验证顺序

1. 访问 `GET http://localhost:3000/api/health` 和 `GET http://localhost:3100/health`。Core 进程启动时会由 `PrismaService` 执行 `SELECT 1`，但健康响应本身只表示进程存活，不是独立的数据库健康响应。
2. 访问 `GET http://localhost:3000/api/assistant/status` 和 Web，确认聚合状态真实反映 Core 数据库与 Agent Runtime；依赖异常时应安全降级，不得泄露内部错误或使用演示数据。
3. 通过内部测试验证 Agent 的 Start/Resume/Events 路由、时间戳 + nonce HMAC 防篡改/防重放和 Capability Header；当前 Events 路由只按 SSE 格式回放截至请求时已持久化的历史并关闭连接，还不是持续推送；也没有公开 Gateway 路由可供浏览器端到端调用。
4. 用真实只读工具查询结构化数据；阶段 0 的 `system-status` 只能通过 Core Internal API 和 Capability 访问。
5. 生成一个不落业务数据的技术 Preview，验证结构化输出、Preview ID、TTL、审计事件、同一幂等键并发只产生一条记录。
6. 在 LangGraph `interrupt` 处暂停，关闭第一个 `PostgresSaver`，用第二个实例在同一 `threadId` 恢复，并确认只读节点不重复执行。这个测试验证的是 LangGraph 检查点，不等于 HTTP Run/Event 元数据已跨进程恢复。
7. 当前仅验证 SSE 编码、事件校验、持久化事件历史读取及 `Last-Event-ID` 补读。Agent Events 端点目前回放当前已存事件后即关闭连接；Start/Resume 也等待图执行完成后返回，尚无运行中的持续事件推送。真实 PostgreSQL 测试覆盖的是 Run 进入 `waiting_for_input` 后正常关闭实例 A，再由实例 B 恢复历史并 Resume；公开 Gateway 和浏览器重连链路未实现。
8. 验证 Agent Runtime 没有 Core 数据库凭证，Capability 不包含 `CONFIRM` 或 `EXECUTE` 权限，Agent 也不能调用确认端点。

金额、余额、权限和业务结论必须来自 Core 结构化结果；Agent、Web 和模型不得自行重算。

## 5. 门禁

每次改动至少执行：

```bash
npm run typecheck
npm run lint
npm test
npm run build
```

阶段0相关改动当前必须覆盖：Core/Agent 契约测试、真实 PostgreSQL 集成测试、Capability 隔离测试、持久化事件历史补读测试和 PostgresSaver 跨实例恢复测试。阶段 0 退出前还必须补齐持续 SSE 推送、断线后按 `Last-Event-ID` 补发遗漏事件的集成测试。无密钥默认测试不得调用 Live Model。

本地真实 PostgreSQL 集成测试可分别执行：

```bash
set -a; source apps/core-api/.env; set +a
npm test -w @piano/core-api

set -a; source apps/agent-runtime/.env; set +a
npm test -w @piano/agent-runtime
```

如果没有相应数据库变量，集成测试会跳过真实数据库部分；这不算集成测试已通过，汇报时必须单独注明。

## 6. 故障排查

- 数据库连接失败：确认 `5433` 是 Core、`5434` 是 Agent；检查两个连接变量是否指向对应数据库，禁止交叉使用。
- Prisma 生成或迁移失败：先执行 `npm run db:generate`，再执行 `npm run db:migrate`；不要修改生成目录或已应用迁移。
- Agent Run/Message/Event 表缺失：先执行 `npm run agent:db:migrate`，再执行 `npm run agent:checkpoint:setup`；前者是项目自有 migration，后者只负责官方 LangGraph 检查点表。
- Agent 启动后 LangGraph 无法恢复线程：确认已单独执行 `npm run agent:checkpoint:setup`，且 `AGENT_DATABASE_URL` 指向 5434；不要在应用启动时隐式建表。若 HTTP Run/Event 历史仍在重启后消失，先检查项目自有 migration、Agent 数据库连接和 repository 日志；它与官方检查点表是两套初始化流程。
- 服务鉴权被拒绝：检查两端 `INTERNAL_SERVICE_SECRET` 是否一致、系统时钟是否同步，以及 HMAC 时间戳、nonce 和请求路径；同一 nonce 重放会被拒绝。
- Capability 被拒绝：检查 Core 的签名私钥、`iss/aud`、`threadId/runId` 和过期时间；Capability 最长 5 分钟。当前 Agent 不单独验证公钥，真正的签名和权限校验在 Core Internal API。
- SSE 断线：不要把 token 放进 URL；用支持 Header 的 fetch 重新连接。当前没有公开 Run 查询 REST 接口；Agent 内部 Events 路由只回放持久化历史后关闭，跨实例历史恢复已通过真实 PostgreSQL 测试，但实时等待新事件和公开 Gateway 端到端仍未实现。
- Run 长时间停在 `running`：当前只有单次图调用超时和并发 Resume 原子抢占，没有 worker 租约、心跳或崩溃回收；不要手工篡改数据库状态，应先保留现场并按待办实现恢复机制。
- AI 不可用：保持 `AI_ENABLED=false`，使用结构化降级页面；Core 和确定性业务入口必须仍能启动。
- 端口被占用：停止对应本地服务或调整本地开发端口；不要改变双数据库的 5433/5434 约定而不同步配置。

## 7. 阶段0退出条件

以下条件全部满足，才能进入阶段1：

- Core、Agent Runtime、Web 和两个 PostgreSQL 的边界可重复启动；
- `PostgresSaver` 的 `interrupt`、跨实例恢复和只读节点不重复执行通过；
- 一个真实只读工具和一个不落业务数据的 Preview 完成端到端验证；
- SSE 断线重连后，Run、工作区和公开结果可从持久化状态恢复；当前仅完成内部事件历史读取和 `waiting_for_input` 状态的跨实例恢复，持续 SSE、公开 Gateway 与工作区恢复均未完成；
- Capability 只能访问授权的只读/Preview 工具，不能确认或执行；
- Agent Runtime 无法连接 Core PostgreSQL；
- 通过 typecheck、lint、unit、build 及阶段0集成/隔离测试；
- 审计记录、错误降级和未调用 Live Model 的默认测试结果可核查；
- 公开 JWT/角色鉴权业务接口和公开 Assistant Gateway Controller 已实现并通过对应验收（当前未满足）。
