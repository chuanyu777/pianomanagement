# AI 业务办理与缴费整改方案

2026-11-05 用户确认：不需要独立的课程开户功能。用户缴费时可调整**单节课价格**，开户与缴费合并办理；其他同类问题按整改方案处理。本文是实施基线，不代表已全部实现或验收。

## 问题和目标

已核实张小鱼存在，主课存在，但她没有课程账户。当前系统先追问收款渠道，再笼统提示找不到账户，没有帮助用户完成缴费；另一处已核实问题是把“他”当作学生姓名，未关联刚确认的张小鱼。通用错误恢复按钮还可能把学生、排课问题一律引向财务页面。

用户无需理解内部账户：输入“张小鱼主课缴费 2000 元，微信”，系统核实学生和课程后，在**一张缴费确认单**展示学生、课程、本次缴费金额、渠道、单节课价格以及缴费前后余额。用户可在确认前调整单节课价格；已有账户则显示现价，只有用户明确修改时才改变，未修改时保持原价。首次缴费的单节价格初始值采用 Core 当前课程默认价，用户可以修改；系统不得猜价格。

确认一次后，Core 将必要的账户建立或价格变更与交费、流水、审计作为一个原子业务操作提交；任何一步失败均不产生部分结果。取消或确认前不产生写入。缴费后的新单价只用于未来需要读取当前价格的业务，既有课消单价快照与历史流水不能被改写。

去掉面向用户的独立“开通课程账户”入口及要求用户先开户的对话步骤。内部仍保留每个学生和课程唯一的账户作为确定性资金模型。查询不创建账户；用户已确认，赠送、排课发现尚无该课程账户时，保持现有冻结规则并引导有权限的店主先缴费，缴费后再继续原业务，不得偷偷收费或虚构数据。

## 同类整改范围

- 学生、课程不存在、同名、停用、退学、无权限、查询故障分别提示，提供有权限且能继续原任务的入口；不把故障当作不存在、不默认创建资料。
- 已确认对象的“他/她/这个学生”仅在同一用户上下文有唯一、可信目标时沿用；不明确时给候选选择。不同学生、课程或角色变化不得误绑。
- 赠送、排课、查询余额及改价的账户前置条件，工资未生成、课程已完成、账期已关闭等路径逐项核对，提供符合领域规则的下一步；不会将用户未要求的业务自动执行。
- 错误恢复按学生、排课、财务等当前任务跳转，而非统一打开财务；状态未知、刷新、取消、并发和恢复时读取 Core 权威状态，保留用户原请求，防止重复确认及重复入账。
- 现行渠道必填；不推测现金、微信或日期，不因合并步骤改变权限和确认要求。

## 实施与验收

1. 在 Core 实现原子缴费预览与确认，包含账户是否存在、原价/新价、业务金额和账户版本校验；余额、金额和价格计算均由 Core 的 Decimal 和领域规则完成。用户确认前后对象、价格、账户或权限发生变化必须重查并重新预览。
2. Web 和 Agent 复用 Core 的权威预览；Agent 只查和申请预览，用户通过浏览器登录态直接确认 Core。账户唯一性依赖数据库约束，并发、幂等与事务回滚须覆盖。
3. 取消、失败、断网、刷新、重复点击、并发与未知结果均不得出现只开户未缴费、只改价未缴费、重复缴费；但用户事后再做正常业务纠错不应改写历史记录。
4. UI、AI 对话和历史恢复都能展示单节价格、本次缴费和渠道的准确业务信息。已存在账户未更改价格、新开户使用默认价或指定价格、已有账户更改价格、多课程与同名、金额和渠道缺失、无权限、停用、退学、关账和数据变化等均需覆盖。
5. 原有 2000 元微信案例必须在隔离环境端到端验证：确认前无账户和缴费，确认一次后账户、所选单价、余额和流水一致；取消时全部不变。同类场景逐项区分已通过、未实现、环境跳过与限制。
6. 新检查先见红再见绿；完成项目 typecheck、lint、test、build，并运行相应真实数据库、API、资金集成测试、业务 smoke 和浏览器端到端检查。默认测试不依赖真实模型；需要模型的验证单独记录。

本次单次确认是用户明确提出的产品调整：一张确认单清楚列出开户（如需要）、价格变化和缴费的全部实际影响，由 Core 作为一个原子动作执行；不沿用“开户后再另行确认缴费”的旧评审方案。实现前应先使冻结需求与该产品决定一致，并按规格执行；不得以 AI 对初始自然语言的理解代替确认。

## 2026-11-06 验证记录

- 完整 typecheck、lint、test 和 build 通过；测试执行 1162 项通过、51 项因环境条件跳过。
- 隔离 PostgreSQL 覆盖新课程首次交费、已有账户改价、关账回滚、重复确认和并发；独立浏览器使用合成数据确认 2000 元交费、单节 180 元后，核对到账户、交费和流水各一条。
- 一次真实模型隔离运行验证建档确认后“他主课缴费 2000 元”再补充“微信”，以及“他隔离测试主课缴费 2000 元，微信”；预览指向刚确认的学生，确认前没有课程账户或交费。对代词与较长课程名的错误拆分，先核查可能的真实学生名与课程；有歧义时要求澄清。相同姓名候选、无权读取和无账户时的预览也有相应隔离或定向检查。
- 赠送、排课无课程账户时按用户决定引导店主先缴费；课程简称复核、课程停用和目录查询失败均有定向测试。上述结果不代表全部自然语言表达、所有异常组合或所有设备上的浏览器体验均已验收。
